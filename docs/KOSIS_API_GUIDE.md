# KOSIS 공유서비스 OpenAPI — 실측 규격

> 규격의 출처는 국가데이터처 **KOSIS 공유서비스 개발가이드**(172쪽, `ref/`)이고,
> 이 문서는 그 위에 **라이브 실측**을 얹은 것이다(2026-09-08).
> 재현: `python scripts/probe_api.py all` · 그때의 실응답은 `tests/fixtures/`.
> 검증 등급 — ✅ 직접 측정 · 📄 문서에만 있음 · ❓ 미확인.

## 0. 🔴 문서만 보고 만들면 반드시 막히는 세 곳

이 API 는 172쪽짜리 가이드가 있는데도 **가장 중요한 세 가지가 그 안에 없거나 틀리다.**

| # | 함정 | 문서 | 실제 |
|---|---|---|---|
| 1 | `jsonVD=Y` | **입력 변수 표에 없음** (JSP 예제 안에만) | 없으면 **JSON 이 아니다** |
| 2 | 통계자료 파라미터 방식 | `statisticsData.do` 아래에 표를 실음 | **`/openapi/Param/statisticsParameterData.do`** 여야 함 |
| 3 | 인증키 | 예제에 인코딩된 문자열 | **디코드하면 안 됨**(그대로 써야 함) |

### 0-1. 🔴 `jsonVD=Y` 가 없으면 JSON 이 아니다

```
format=json           → [{LIST_NM:"인구총조사",LIST_ID:"A_4"}]      ← json.loads 실패
format=json&jsonVD=Y  → [{"LIST_NM":"인구총조사","LIST_ID":"A_4"}]   ← 정상
```

✅ 실측. 키에 따옴표가 없는 **자바스크립트 객체 리터럴**이 온다. `jsonVD=N` 도 같다.
개발가이드의 **입력 변수 표에는 이 파라미터가 아예 없고**, JSP 예제 소스 안에만 있다
(p20 등). 표만 보고 만들면 파서가 첫 응답에서 죽는다.

### 0-2. 🔴 통계자료를 `orgId/tblId` 로 부르려면 경로가 다르다

개발가이드 p39 는 '통계표선택 방법'의 입력 변수를 `statisticsData.do` 아래에 싣는다.
그런데 그 URL 로 `orgId`·`tblId`·`objL1`·`itmId`·`prdSe` 를 아무리 맞춰 보내도
**항상 `err 20`(필수요청변수 누락)** 이다(✅ 실측, 조합 11가지 시도).

실제 경로는:

```
https://kosis.kr/openapi/Param/statisticsParameterData.do
```

✅ 이 경로로 같은 파라미터를 보내면 885행이 정상으로 온다. 가이드의 **예제 URL 은 전부
`userStatsId`(자료등록 방식)뿐**이라 이 경로가 문서 어디에도 나오지 않는다.

- `statisticsData.do` — `userStatsId` 방식(미리 등록한 자료). ✅ `method=getMeta` 로 메타자료.
- `Param/statisticsParameterData.do` — `orgId`/`tblId` 방식(등록 불필요).

### 0-3. 🔴 인증키를 디코드하지 말 것

KOSIS 인증키는 base64 로 보이고 실제로 base64 지만, **발급된 문자열 그대로** 보내야 한다.

| 보낸 형태 | 결과 |
|---|---|
| 발급값 그대로 | ✅ 정상 |
| base64 디코드한 값 | ❌ `{"err":"11","errMsg":"유효하지않은 인증KEY입니다."}` |

## 1. 엔드포인트

| 서비스 | URL |

| 통계자료(파라미터) | **`kosis.kr/openapi/Param/statisticsParameterData.do`** |

| 대용량 | `kosis.kr/openapi/statisticsBigData.do` — 🔴 **인증이 서비스별로 갈린다**(§6). 이 저장소는 쓰지 않는다 |

## 2. 🔴 모든 실패가 HTTP 200 이다

✅ 실측. **성공은 배열, 실패는 객체** — 이 구분이 가장 확실한 판별 기준이다.

```json
{"err":"11","errMsg":"유효하지않은 인증KEY입니다."}
```

⚠️ `Content-Type` 은 성공·실패 모두 `text/html;charset=UTF-8` 이다. 믿지 말 것.
⚠️ 대용량 서비스만 **XML** 로 오류를 준다(`<error><err>11</err></error>`) — §6.

| 코드 | 문서 | ✅ 실제 관측 |
|---|---|---|
| 10 | 인증키 누락 | "인증KEY값이 누락되었습니다." |
| 11 | 인증키 **기간만료** | "유효하지않은 인증KEY입니다." — 잘못된 키에도 11 이 온다 |
| 20 | 필수요청변수 누락 | 확인 (§0-2 의 경로 문제도 이 코드다) |
| 21 | 잘못된 요청변수 | 확인 |
| 30 | 조회결과 없음 | 확인 — **오류가 아니라 사실이다** |
| 31 | 조회결과 초과 | 확인 — 4만 셀 제한(§3) |
| 40 | 호출가능건수 제한 **분당 200건** | 📄 |
| 41 | 호출가능 ROW 수 제한 | 📄 |
| 42 | 사용자별 이용 제한 | 📄 |
| 50 | 서버오류 | 📄 |

⚠️ **`method` 를 빠뜨리면 오류가 아니라 빈 본문**이 온다(✅ 실측). '결과 0건'으로
읽으면 조용한 사고다.

## 3. 🔴 요청당 4만 셀 — `err 31` 은 실패가 아니라 분할 신호다

개발가이드 p33: "시스템 부하를 줄이기 위해 통계자료 요청은 4만 셀 이하로 제한".

✅ 실측(`DT_1B040A3`, 월별, objL1=ALL·itmId=ALL — 시점당 약 885행):

| 요청 | 결과 |
|---|---|
| `newEstPrdCnt=12` | ✅ 10,590행 |
| `newEstPrdCnt=60` | ❌ `err 31` |
| `startPrdDe=202101&endPrdDe=202512`(60개월) | ❌ 단발로는 `err 31` |

→ 이 저장소의 `kosis_data` 는 **기간을 절반씩 쪼개 자동으로 다시 부른다.**
   ✅ 위 60개월 구간을 **3회 요청으로 52,587행 전수** 회수했다(구간이 겹치지 않게 분할).

⚠️ `recent`(최근 N개) 방식은 쪼갤 축이 없어 자동 분할이 안 된다 — 기간을 주면 된다.
⚠️ 한 시점만으로도 넘으면 분류(`objL1`~`objL8`)나 항목(`itmId`)을 좁혀야 한다 — §4 참조.

## 4. 🔴 분류축(`objL`) 개수가 **정확히** 맞아야 한다

개발가이드는 `objL2`~`objL8` 을 "선택"으로 적는다. **틀렸다.** 표의 분류축이 2개면
`objL` 도 정확히 2개여야 한다 — 모자라도, 넘쳐도 실패한다.

✅ 실측(`118/DT_118N_MON051` 「산업/규모별 임금 및 근로시간」, 2026-09-08):

| 보낸 축 | 결과 |
|---|---|
| `objL1=ALL` | ❌ `err 20` — `필수요청변수값이 누락되었습니다. (objL)` |
| `objL1=ALL&objL2=ALL` | ✅ **34,496행** (산업분류 × 규모별) |
| `objL1=ALL&objL2..objL8=ALL` | ❌ `err 21` — `잘못된 요청 변수를 호출 하였습니다.` |

🔴 **그런데 축 개수를 알려 주는 메타 서비스가 없다.**

| 시도 | 결과 |
|---|---|
| `type=NCD` | 분류가 아니라 **시점별 수록일자**(`PRD_DE`·`SEND_DE`)가 온다 |
| `type=OBJ` · `type=CLS` | `err 30`(자료 없음) |

→ 그래서 이 저장소의 `kosis_data` 는 **`objL1` 부터 시작해 `err 20 (objL)` 을 만날
   때마다 축을 하나씩 늘린다.** 모자라면 20·넘치면 21이므로 **아래에서 위로 올라가는
   방향만 안전하다.** 확정된 축은 뒤따르는 분할 요청이 물려받아 탐색은 한 번뿐이다.
   결과의 `meta.obj_levels` 에 확정된 축이, `meta.obj_note` 에 그 사실이 실린다.

⚠️ **`err 20` 은 원인이 둘이다** — 엔드포인트를 틀렸거나(§0-2), 축을 덜 보냈거나.
   KOSIS 가 후자에만 `(objL)` 을 붙여 주므로 그것으로 가른다. 섞으면 축을 늘려도
   영영 낫지 않는 요청을 8번 반복하게 된다.

⚠️ 빈 축을 보내면 안 된다 — `objL3=` 처럼 값이 비어도 **개수에는 들어간다.**

### 4-1. 축 승급과 기간 분할은 **함께 돈다** (✅ 실측)

두 자동 기전이 겹치는 경우가 실제로 가장 흔하다 — 축이 여럿인 표는 시점당 행이 많아
4만 셀에도 잘 걸린다. `118/DT_118N_MON051` 을 반기 `202001~202402` 로 부른 결과:

```
수집 172,480행 · 요청 12회
확정 축 : {'objL1': 'ALL', 'objL2': 'ALL'}   ← 탐색은 처음 한 번뿐
구간    : 202001~202007 · 202101 · 202102~202201 · 202202~202208 ·
          202301~202302 · 202401~202402      ← 겹침 없음
시점 10개 × 17,248행 = 172,480              ← 누락도 중복도 없다
```

⚠️ 분할 경계에 `202007`·`202208` 처럼 **반기에 없는 값**이 나온다. `_midpoint` 가
   월 산술로 중간을 잡기 때문인데, 무효값이 그 해의 유효 시점들 **뒤**에 정렬되고
   `_next_period` 가 다음 해 1기로 넘겨 주므로 구간은 정확히 맞물린다(위 검산).

## 5. 페이징이 없다 — **단, 통계주요지표는 예외다**

통합검색·통계목록·통계자료에는 페이징 파라미터가 **문서에도 없고 실제로도 없다**.
서버가 준 만큼이 전부이므로, 더 필요하면 검색어를 좁혀야 한다.
이 저장소는 그 사실을 `truncated_note` 로 알린다(조용히 자르지 않는다).

🔴 **통계주요지표 계열(§7)만 `pageNo`·`numOfRows` 를 받는다.** 그리고 안 주면
   **10건만 온다.** 다른 서비스의 습관("주는 만큼이 전부")을 그대로 가져가면
   113건짜리 결과를 10건으로 읽는다 — 이 API 안에서 규칙이 갈리는 유일한 자리다.

## 6. 🔴 대용량(BigData)은 **인증이 따로 논다**

`statisticsBigData.do` 는 다른 서비스와 **같은 키로 `err 11`(유효하지않은 인증KEY)** 을
돌려준다. 키가 잘못된 것이 아니다 — ✅ 실측(2026-09-08, 5가지 조합):

| 요청 | 결과 |
|---|---|
| 대용량 + `orgId`/`tblId` | ❌ `err 11` (XML) |
| 대용량 + `userStatsId` | ❌ `err 11` (XML) |
| 대용량, **`method` 조차 없이** | ❌ `err 11` (XML) |
| 대용량 + `format=xml` | ❌ `err 11` (XML) |
| **대조**: 같은 키로 통계목록 | ✅ 30건 정상 |

`method` 도 없는 요청에 같은 답이 온다는 것은 **파라미터 검증 이전에 키가 거부된다**는
뜻이고, 같은 키가 다른 서비스에서 전부 정상이라는 것과 합치면 결론은 하나다 —
**인증이 서비스별로 갈리고, 이 키는 대용량에 승인돼 있지 않다.**

⚠️ 오류가 **항상 XML** 로 온다. `format=json&jsonVD=Y` 를 줘도 그렇다 — 파서가
   `<err>` 를 읽는 갈래를 따로 두는 이유가 이것이다.
⚠️ `/openapi/Param/statisticsBigData.do` 는 **404** 다. `Param` 경로는 통계자료
   파라미터 방식(§0-2) 전용이지 대용량과는 무관하다.

→ 이 저장소의 도구는 대용량을 **쓰지 않는다.** 다만 `kosis_status` 가 승인 여부를
   재서 알린다 — 그러지 않으면 `err 11` 만 보고 **멀쩡한 키를 재발급하러 가기 때문**이다.

### 6-1. 라이선스 제약 자료는 서비스에서 제외된다 (📄 문서 · 실측으로는 재현 못 함)

개발가이드: "통계자료와 대용량 통계자료는 **국제통계 등 라이선스 제약에 해당되는
자료는 서비스 제외**".

✅ 그런데 재현되지 않았다(2026-09-08). 국제통계 트리(`MT_RTITLE`)에서 훑은 47개 표와
OECD·IMF 계열 표들이 **전부 정상으로 수치를 준다**:

| 표 | 결과 |
|---|---|
| `101/DT_2OEEM3018` 실업 인구 (OECD) | ✅ 1,382행 |
| `101/DT_2OEHG072` 65세 기대수명 (OECD) | ✅ 6행 |
| `101/DT_2WEO007` 세계총생산 중 GDP 비중 (IMF WEO) | ✅ 182행 |
| `101/DT_2KAA101` 국토면적 (국제통계 트리) | ✅ 3,963행 |

→ 제외가 **광범위하지는 않다.** 다만 표 단위로 걸리는 것을 배제할 수 없다.

🔴 문제는 **응답으로 구분이 안 된다**는 것이다. 라이선스 제외든 정말 자료가 없든
   똑같이 `err 30` 이다. 그래서 `kosis_data` 의 0건 응답은 두 가능성을 **둘 다**
   적어 준다 — 한쪽만 말하면 사용자가 엉뚱한 곳을 뒤진다.

⚠️ 이 제약은 §6 의 대용량 `err 11` 을 **설명하지 못한다.** 라이선스 제외는 자료 층의
   이야기인데, 대용량은 `method` 조차 없는 요청에도 `err 11` 이다 — 파라미터를 보기도
   전에 키가 거부된다. 두 사실은 층이 다르다.

## 7. 통계주요지표 — 규칙이 다른 계열 (✅ 실측)

개발가이드 §2.7. 통계표(TBL_ID)가 아니라 **지표(statJipyoId)** 를 다루는 별도 계열로,
하위 서비스가 6종이다. ✅ **같은 인증키로 전부 접근된다**(대용량과 달리 err 20 이지
err 11 이 아니다 — 즉 인증은 통과하고 파라미터만 맞추면 된다).

| # | 서비스 | URL | 필수 |
|---|---|---|---|
| 2.7.3.1 | 지표 고유번호별 설명자료 | `pkNumberService.do` | `jipyoId` |
| 2.7.3.2 | 지표명별 설명자료 | `indExpService.do` | `jipyoNm` |
| 2.7.3.3 | 목록별 지표조회 | `indiListService.do` | `listId` |
| 2.7.3.4 | 지표명별 목록조회 | `indListSearchRequest.do` | `jipyoNm` |
| 2.7.3.5 | 고유번호별 목록조회 | `indListSearchRequest.do` (같은 URL) | `jipyoId` |
| 2.7.3.6 | 고유번호별 지표 상세조회 | `indIdDetailSearchRequest.do` | `jipyoId` + 시점 |

공통 고정 파라미터는 `method=getList` 와 `service=1~4`(+ 일부는 `serviceDetail`)다.
✅ `jsonVD=Y` 함정은 **여기에도 그대로 있다** — 없으면 자바스크립트 리터럴이 온다.
✅ `listId` 는 통계목록(`vwCd` 트리)의 `LIST_ID` 와 같은 공간이다(`listId=A` 로 확인).

### 7-1. 🔴 페이징이 있고, 안 주면 **10건에서 잘린다**

```
jipyoNm=인구 · 파라미터 없음            → 10건
jipyoNm=인구 · numOfRows=100           → 100건
jipyoNm=인구 · numOfRows=100&pageNo=2  → 13건   (전수 113건)
```

✅ `numOfRows=50` 으로 페이지를 넘겨 가며 **짧은 쪽이 나올 때까지** 돌면 50+50+13 =
**113건 전수**를 겹침 없이 회수한다(고유 지표ID 113개, 중복 0).

⚠️ **총건수를 알려 주는 필드가 응답에 없다.** 전수를 받았는지 판단할 근거는
   "마지막 쪽이 `numOfRows` 보다 짧다"뿐이다. 정확히 배수로 떨어지면 한 번 더 불러
   빈 쪽을 확인해야 한다.

### 7-2. 🔴 `startPrdDe`/`endPrdDe` 는 **거르지 않는다** — 모드 스위치일 뿐이다

지표 상세조회(2.7.3.6)의 시점 파라미터는 값이 무시된다:

| 요청 (`jipyoId=13` 합계출산율) | 결과 |
|---|---|
| 시점 파라미터 없음 | ❌ `err 30` (자료 없음) |
| `startPrdDe=2015&endPrdDe=2025` · `numOfRows=200` | 56건 · **시점 1970~2025** |
| `startPrdDe=2020&endPrdDe=2020` · `numOfRows=200` | 56건 · **시점 1970~2025** (동일) |
| `rn=5` 단독 | ❌ `err 30` |
| `rn=5&srvRn=5` | 5건 · 2016~2020 |

→ 시점 파라미터는 **"시점기준 모드를 켠다"는 플래그**로만 작동하고 범위는 서버가
   무시한다. 필터로 믿으면 **요청하지 않은 전 구간을 받고도 모른다.** 좁히려면
   받은 뒤 직접 걸러야 한다.

⚠️ **`err 30` 의 뜻이 여기서만 다르다.** 다른 서비스에서 `err 30` 은 '자료 없음'인데,
   여기서는 **모드를 안 골랐다**(시점기준·최신자료기준 중 하나를 줘야 한다)는 뜻일 수
   있다. `rn` 도 `srvRn` 과 **함께** 줘야 한다 — 단독으로는 `err 30` 이다.

### 7-3. 응답 모양

목록조회: `statJipyoId`·`statJipyoNm`·`unit`·`areaTypeName`·`prdSeName`·
`strtPrdDe`·`endPrdDe`·`rn`(수록시점개수)·`prdDe`.
상세조회(수치): `statJipyoId`·`statJipyoNm`·`itmNm`(지역 등)·`prdSe`·`prdDe`·`val`.

```json
{"itmNm":"전국","prdDe":"1970","prdSe":"Y","statJipyoId":"13",
 "statJipyoNm":"합계출산율","val":"4.530"}
```

⚠️ 수치 칸 이름이 통계자료의 `DT` 가 아니라 **`val`** 이고, 시점도 `PRD_DE` 가 아니라
   **`prdDe`**(소문자 카멜)다. 계열이 다르면 대소문자 규칙도 다르다 — 통계자료의
   파서를 그대로 쓰면 전부 빈 값이 된다.

## 8. 문서와 다른 것들

- ✅ **`parentListId` 는 필수가 아니다.** 개발가이드 p19 는 필수라 적지만, 생략하면
  **최상위 목록**이 온다(주제별 30건). 트리를 뿌리부터 훑는 입구가 이것이다.
- ✅ **`method` 값은 검증되지 않는다.** `method=nope` 로 보내도 정상 결과가 온다.
- ⚠️ 개발가이드가 항목/분류 전체선택을 `all`(소문자)로 적지만 `ALL` 도 통한다(✅ 실측).
- ✅ **`type=NCD` 는 분류가 아니다.** 응답이 시점별 수록일자(`PRD_DE`·`SEND_DE`)로
  오고 분류 코드는 한 칸도 없다(표 2개에서 확인). 분류축은 §4 를 볼 것.
- ✅ **없는 메타 `type` 은 `err 21` 이 아니라 `err 30`(자료 없음)을 준다**(`OBJ`·`CLS` 실측).
  오타와 '정말 0건'이 구분되지 않으므로 `META_TYPES` 화이트리스트가 유일한 방어선이다.

## 9. 응답 필드 (✅ 실측)

**통합검색** — `ORG_ID`·`ORG_NM`·`TBL_ID`·`TBL_NM`·`STAT_ID`·`STAT_NM`·`VW_CD`·
`MT_ATITLE`(분류 경로)·`STRT_PRD_DE`·`END_PRD_DE`·`TBL_VIEW_URL`·`CONTENTS` 등 18개.

**통계자료** — `ORG_ID`·`TBL_ID`·`TBL_NM`·`C1`~`C8`(분류값 ID)·`C1_NM`~(분류값 명)·
`C1_OBJ_NM`~(분류 이름)·`ITM_ID`·`ITM_NM`·`UNIT_NM`·`PRD_SE`·`PRD_DE`·`DT`(수치)·`LST_CHN_DE`.

⚠️ **분류 축의 개수가 표마다 다르다**(2~8은 없으면 생략). 고정 스키마를 강요하면
분류가 통째로 사라진다 — 이 저장소는 분류 이름을 그대로 열로 쓴다.

⚠️ 통계설명 본문에 **두 번 이스케이프된** 엔티티가 온다(`&amp;ldquo;`). 한 번만
풀면 `&ldquo;` 가 화면에 남는다.

## 10. 예의

분당 200건 제한이 있으므로 기본 throttle 을 **0.35초**(≈171회/분)로 둔다.
`err 40` 이 나면 기다렸다가 재시도한다(재시도가 의미 있는 몇 안 되는 코드다).
